# Руководство по запуску и настройке

Как развернуть MVP AI-системы для свитч-трейдинга, где взять ключи и куда их
вносить. Документ для заказчика/администратора.

---

## 1. Что это и что нужно

Telegram-бот: присылаете тикер акции США (например `NVDA`) → бот собирает данные,
считает 7 факторных Score и Final Score (0–100), применяет Risk Filter и отвечает
метриками, оценкой и историей сигналов.

Что нужно для запуска:
- **VPS** (сервер): Ubuntu 22.04+, ≥ 2 vCPU / 4 GB RAM, установлены **Docker** и
  **docker compose**.
- **API-ключи** сервисов данных, токен Telegram-бота и ключ LLM (см. раздел 2).
- Доступ по SSH к серверу.

> Платные API (FMP и т.д.) и фактическое потребление LLM оплачиваются заказчиком
> отдельно от стоимости разработки — это зафиксировано в КП.

## 2. Где взять ключи

| Сервис | Зачем | Тариф для MVP | Где получить |
|---|---|---|---|
| **Financial Modeling Prep (FMP)** | Основной источник: котировки, история цен, fundamentals, earnings, новости | **Starter $29/мес** (минимум — включает Annual Fundamentals & Ratios, Historical Stock Price, Financial Market News, US Coverage). Basic (Free) не подходит — без fundamentals/news. Premium $69 избыточен для MVP | https://site.financialmodelingprep.com/pricing-plans → регистрация → раздел Dashboard/API Keys |
| **SEC EDGAR** | Официальные филинги (10-K/10-Q/8-K) | Бесплатно, **без ключа** | Ключ не нужен. Требуется только корректный `User-Agent` (название проекта + email) |
| **Alpaca** | Резервный источник котировок | Basic — бесплатно | https://alpaca.markets → Sign up → Paper/Live → API Keys (Key ID + Secret) |
| **Finnhub** | Резерв новостей / news sentiment | Free | https://finnhub.io → регистрация → Dashboard → API Key |
| **Telegram Bot** | Интерфейс | Бесплатно | В Telegram напишите **@BotFather** → `/newbot` → получите **токен** |
| **LLM — Anthropic (Claude)** | AI-объяснение | Оплата по токенам (доли цента за запрос) | https://console.anthropic.com → API Keys |
| **LLM — OpenAI** *(альтернатива)* | AI-объяснение | Оплата по токенам | https://platform.openai.com → API Keys |

> использовать по умолчанию, согласуем перед развёртыванием.

## 3. Куда вносить ключи

Все секреты хранятся в файле **`.env`** в корне проекта (он не попадает в git).
Скопируйте шаблон и заполните значения:

```bash
cp .env.example .env
nano .env   # или любой редактор
```

Поля файла `.env`:

```dotenv
# --- Источники данных ---
FMP_API_KEY=<ключ FMP>                         # ОБЯЗАТЕЛЬНО
# ОБЯЗАТЕЛЬНО. Формат: "<название проекта> <контактный email>" — реальный email.
# SEC требует контактный email в каждом запросе (иначе блокировка 403);
# с плейсхолдером example.com сервисы не запустятся.
SEC_USER_AGENT=switch-trading-mvp your-email@example.com
ALPACA_API_KEY_ID=<Key ID из Alpaca>
ALPACA_API_SECRET_KEY=<Secret из Alpaca>
ALPACA_DATA_FEED=iex                           # iex — бесплатный (объёмы одной биржи), sip — платный
FINNHUB_API_KEY=<ключ Finnhub>

# --- Telegram ---
TELEGRAM_BOT_TOKEN=<токен от @BotFather>       # ОБЯЗАТЕЛЬНО
TELEGRAM_ALLOWED_IDS=12345,67890                # ОБЯЗАТЕЛЬНО: Telegram ID через запятую (или один ID)
TELEGRAM_ALLOW_PUBLIC=false                     # true — открыть бот всем (только осознанно)

# --- LLM (Этап 2) ---
LLM_PROVIDER=claude              # claude | openai
ANTHROPIC_API_KEY=<ключ Anthropic>
OPENAI_API_KEY=<ключ OpenAI>     # если выбран openai

# --- База данных (по умолчанию поднимается в docker) ---
POSTGRES_USER=switch
POSTGRES_PASSWORD=<придумайте пароль>          # ОБЯЗАТЕЛЬНО
POSTGRES_DB=switch_trading
```

Остальные поля (`*_BASE_URL`, таймауты, интервал проверки источников
`HEALTH_PROBE_INTERVAL_SECONDS`) можно оставить по умолчанию. Если обязательное
поле не заполнено, API и бот не запустятся и выведут в логах перечень ошибок
(`docker compose logs app bot`). Свой Telegram ID можно узнать у бота
@userinfobot.

> ⚠️ Не пересылайте `.env` и ключи в открытых чатах. Передавайте по защищённому
> каналу.

Бизнес-настройки (веса Score, пороги Risk/Rule Engine) вынесены отдельно в
`config/thresholds.yaml` — их можно менять без правки кода.

## 4. Запуск на сервере (Docker)

```bash
# 1. Клонировать проект и перейти в папку
git clone <репозиторий> && cd ai-trading

# 2. Заполнить .env (см. раздел 3)
cp .env.example .env && nano .env

# 3. Поднять PostgreSQL, применить миграции и запустить API + Telegram-бота
docker compose up -d --build

# 4. Проверить, что сервис жив
curl http://localhost:8000/health

# 5. Проверить контейнеры и логи бота
docker compose ps
docker compose logs --tail=100 bot
```

`/health` вернёт статус приложения и по каждому источнику данных (статус, задержка,
счётчик ошибок) — по нему видно, что ключи рабочие и данные приходят.

> Telegram-бот запускается отдельным Compose-сервисом (long polling, публичный
> домен не нужен). PostgreSQL не имеет внешнего порта, а API опубликован только
> как `127.0.0.1:8000`; для удалённой проверки используйте SSH-туннель.

```bash
ssh -L 8000:127.0.0.1:8000 <user>@<server>
# затем локально: curl http://127.0.0.1:8000/health
```

## 5. Как пользоваться ботом

1. Найдите своего бота в Telegram по имени, которое задали в @BotFather.
2. Отправьте `/start` — краткая инструкция.
3. Отправьте тикер: `NVDA` или `$AAPL`.
4. В ответ — компания, текущая котировка и закрытие EOD, Final Score (с пометкой
   «достоверность: высокая / пониженная»; если данных недостаточно — «не
   рассчитан» с причинами), 7 факторных Score,
   оценка риска и кнопки:
   **Подробнее** (расшифровка факторов), **Метрики** (исходные значения),
   **Risk** (флаги риска с причинами), **История**.
5. Команда `/history NVDA` — последние сигналы по тикеру.

Каждое сообщение содержит дисклеймер «Не является индивидуальной инвестиционной
рекомендацией».

## 7. Частые вопросы

- **«Тикер … не найден»** — проверьте написание; тикер должен существовать на
  US-рынке и быть доступен в FMP.
- **«превышено время ожидания» / «сетевая ошибка» / «лимит запросов» /
  «ключ или тариф»** — сбой источника с указанием причины; смотрите `/health`.
  Расчёт в этом случае не сохраняется, торговый вывод не выдаётся.
- **«достоверность: пониженная»** — часть некритичных данных недоступна
  (история 200–249 дней, нет SEC или новостей, неизвестна дата отчётности
  и т. п.); причины перечислены в сообщении и в кнопке «Risk».
- **«Final Score не рассчитан — недостаточно данных»** — не хватает критичных
  данных (история < 200 дней, нет бенчмарка SPY, нет ≥ 3 ключевых показателей
  отчётности, не рассчитан фактор); Score намеренно не выдаётся.
- **Где посмотреть, какой источник использован** — в `/health` и в сохранённом
  сигнале фиксируется источник и время получения данных.
- **Как поменять пороги/веса** — отредактируйте `config/thresholds.yaml`; каждый
  расчёт хранит версию формул, поэтому история остаётся сравнимой.
- **Резервное копирование, мониторинг, обновление** — `docs/OPERATIONS.md`.
